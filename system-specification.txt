# BlockBoard Cosmos

A Cosmos-SDK + CosmWasm implementation of the **BlockBoard** on‑chain message board. This project mirrors the EVM version in **functionality, UX intent, and learning goals**, while teaching Cosmos-native concepts: Tendermint consensus, validators, gas, WASM contracts, and Keplr wallet integration.

---

## 1. Purpose & Learning Goals

**Functional parity with EVM BlockBoard**

* Post a message (≤ 140 characters)
* Read last message
* Read message count

**What you will learn (Cosmos-specific)**

* Cosmos SDK architecture
* Tendermint (PoS + BFT) block production
* CosmWasm smart contracts (Rust → WASM)
* Keplr wallet + signing flow
* Gas & fees in Cosmos
* Local chain vs public testnet workflow

This is a **100% free, local-first** learning project.

---

## 2. System Overview (High-Level)

```
User (Browser)
   ↓ Keplr Wallet (sign tx)
Frontend (React)
   ↓ CosmJS
Cosmos Node (Local)
   ↓
CosmWasm Smart Contract
```

There is **no backend server**. The blockchain itself is the backend.

## 4. Smart Contract Specification (CosmWasm)

### 4.1 Contract State

```rust
pub struct State {
    pub last_message: String,
    pub message_count: u64,
}
```

* Stored on-chain
* Persists across blocks and restarts

---

### 4.2 Execute Messages

```rust
PostMessage { message: String }
```

**Rules**

* Message length ≤ 140 characters
* Empty messages rejected

**Behavior**

* Update `last_message`
* Increment `message_count`
* Emit event `message_posted`

---

### 4.3 Query Messages

```rust
GetLastMessage {}
GetMessageCount {}
```

Used by frontend to read chain state.

---

### 4.4 Contract Entry Points

| Function    | Purpose                |
| ----------- | ---------------------- |
| instantiate | Initialize state       |
| execute     | Handle transactions    |
| query       | Read-only state access |

## 5. Frontend Specification (React)

### 5.1 Wallet Integration

* Wallet: **Keplr** (free browser extension)
* Connection via `window.keplr`
* Chain: Local Cosmos chain or public testnet

---

### 5.2 UI Layout (Matches EVM Version)

```
┌──────────────────────────┐
│ BlockBoard Cosmos        │
│ [ Connect Wallet ]       │
│                          │
│ Last Message: "..."     │
│ Message Count: 5         │
│                          │
│ [ Text Input Box ]       │
│ [ Post Message ]         │
│                          │
│ Status: Tx Pending...    │
└──────────────────────────┘
```

**UI Rules**

* Button disabled until wallet connected
* Clear status text (idle / pending / success / error)
* Simple neutral colors (same UX logic as EVM)

---

### 5.3 Frontend Logic Flow

1. User clicks **Connect Wallet**
2. Keplr approves connection
3. Frontend creates CosmJS signing client
4. Reads contract state via query
5. User submits message
6. Transaction signed in Keplr
7. Block confirmation
8. UI refreshes state

## 6. Local Blockchain Setup (Free)

### Required (Outside VS Code)

| Tool         | Why                    |
| ------------ | ---------------------- |
| Keplr Wallet | Signing transactions   |
| Docker       | Run local Cosmos chain |
| Rust         | Build WASM contract    |
| Node.js      | Frontend tooling       |

---

### Local Chain Choice

**Option A (Recommended)**

* Use `wasmd` Docker image (CosmWasm-enabled chain)
* Single-validator
* Free and fast

**Option B (Advanced)**

* Ignite CLI
* Custom Cosmos SDK chain

This project assumes **Option A**.

---

## 7. Build & Run Instructions (Correct Order)

### Step 1 – Start Local Chain

```bash
docker run -p 26657:26657 -p 1317:1317 cosmwasm/wasmd
```

---

### Step 2 – Compile Contract

```bash
cd contracts
cargo wasm
```

---

### Step 3 – Upload & Instantiate Contract

```bash
wasmd tx wasm store blockboard.wasm
wasmd tx wasm instantiate ...
```

Contract address is saved to `frontend/config.js`.

---

### Step 4 – Run Frontend

```bash
cd frontend
npm install
npm run dev
```
